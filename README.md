## 개발 방향 및 뼈대

- 팀 프로젝트에서 원활한 개개인의 개발을 위해 **모듈화와 추상화에 초점**을 두어 SW를 개발함.
  - 각 미션에 대해 필요한 기능들(예를 들어, 차선 인식이나 우선 정지 장애물 여부 인식 등)을 최대한 독립적인 개발 프로세스로 나누어 모듈화를 진행함.
  - 각 미션에 대한 Recognize(인식)와 Process(처리 및 제어)를 분리하고, Process 단계에서 Recognize 단계의 데이터 전처리 과정을 몰라도 Recogznie 단계의 추상화 정보만으로 데이터를 활용할 수 있도록 함.
- 리눅스의 Message Queue를 활용하여 제어 보드에 여러 프로세스(스레드)가 접근할 수 있도록 ctrlboard 프로세스를 개발함. ([개발 문서](./src/ctrlboard/README.md))
- 리눅스의 Shared Memory를 활용하여 Recognize 프로세스에서 생산한 정보를 다른 프로세스들과 함께 공유할 수 있도록 함.
- 모형차의 실질적인 제어를 담당하는 Process 프로세스는 다음의 목표를 따라 구현되었다. ([개발 문서](./src/process/README.md))
  - 고속 동작: 정보를 처리하는 과정에 있어 Blocking Operation(하드웨어 통신을 기다리는 동작, 영상 처리 수행 등)이 있어서는 안 된다.
  - 독립적 개발: Recognize 파트가 모두 구현되었다는 조건 하에 각 미션 처리 및 제어에 대해 독립적으로 작동이 가능해야 한다.
  - 개발의 편의성: 개발을 시작하기 위해 해야 하는 초기 설정과 건드려야 하는 파일을 최대한 줄인다.
  - 개발의 보편성: 복잡한 전처리기나 쉘 스크립트를 이용한 트릭 등은 최대한 줄여서 추후 유지보수를 쉽게 만든다.
  - Stateless: 함수의 출력은 오직 함수의 입력에 대해서만 결정되어야 하며, 전역 변수 등과 같은 Side Effect를 불러 일으킬 수 있는 요소는 최대한 지양한다(전역 변수나 Random 함수 등을 사용하면 함수의 출력을 예측하기 힘듦).



## 브랜치

- `master`: `./run.sh`를 실행하면 바로 정상 동작이 가능한 코드. 새로운 기능을 추가할 때 여기서 브랜치를 만들어 작업하면 된다.
- `draft`: 각자 작성한 개개인의 코드를 합쳐서 제대로 동작하는지 테스트해보는 브랜치. 제대로 동작한다면 master 브랜치에 merge한다.
- `mission-1`: 3차 교육 전에 수행해야 할 미션(자동 실행, 영상 처리 후 소요 시간 출력, 특정 물체를 인식후 따라가게 만들기)을 구현한 코드.
